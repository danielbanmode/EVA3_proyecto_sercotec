1. COMPONENTES REUTILIZABLES Y MODULARIDAD
================================================================================

DEFINICIÓN:
Crear componentes que encapsulen lógica y presentación, permitiendo reutilización
y mantenimiento simplificado.

IMPLEMENTACIÓN EN PROYECTO:

✅ ServiceCard.jsx - Componente reutilizable para tarjetas de servicio
   - Props: id, titulo, descripcion, imagen, servicio
   - Uso: Renderizado en loop en Home.jsx con .map()
   - Ventaja: Una sola definición, 6 tarjetas diferentes
   
✅ TestimonialsCarousel.jsx - Componente independiente de carrusel
   - Props: testimonials (array)
   - Encapsula: State del carrusel, navegación, auto-play
   - Ventaja: Totalmente reutilizable en otras páginas

✅ ContactForm.jsx - Componente de formulario aislado
   - Props: servicio (pre-rellena desde URL)
   - Encapsula: Validación, estado del formulario, lógica de envío
   - Ventaja: Usado en /contacto y reutilizable en modales

CÓDIGO EJEMPLO:

// ❌ INCORRECTO: Componente monolítico
function HomePage() {
  return (
    <div>
      {/* 500+ líneas de código aquí */}
      <button>Contacto</button>
    </div>
  )
}

// ✅ CORRECTO: Componentes separados
function HomePage() {
  return (
    <div>
      <Header />
      <Services />
      <Testimonials />
      <ContactButton />
    </div>
  )
}

BENEFICIOS:
- Fácil de testear
- Reutilizable en múltiples lugares
- Fácil de mantener
- Código más limpio

2. SEPARACIÓN DE RESPONSABILIDADES (JSX + CSS + Lógica)
================================================================================

DEFINICIÓN:
Cada componente tiene: su JSX, su CSS, y su lógica (states/hooks) separados
pero relacionados.

ESTRUCTURA POR CARPETA:

src/components/ServiceCard/
├── ServiceCard.jsx     (Componente + Lógica)
└── ServiceCard.css     (Estilos específicos)

VENTAJAS:
- Fácil localizar estilos de un componente
- Cambiar estilos sin tocar lógica
- Escalabilidad: Agregar componentes sin desorden

CÓDIGO EJEMPLO:

// ServiceCard.jsx - LÓGICA Y JSX
import './ServiceCard.css'

function ServiceCard({ titulo, descripcion, imagen, servicio }) {
  const handleContactClick = () => {
    // Navegación a formulario
  }

  return (
    <div className="service-card">

      <h3>{titulo}</h3>
      <p>{descripcion}</p>

3. USO DE HOOKS DE REACT (useState, useEffect, useSearchParams)
================================================================================

DEFINICIÓN:
Utilizar hooks para manejar estado, efectos secundarios y lógica de componentes
funcionales.

IMPLEMENTACIÓN:

✅ useState - Manejar estado local
   Uso: Abrir/cerrar menú, carrusel actual, form fields

   const [isOpen, setIsOpen] = useState(false)
   const toggleMenu = () => setIsOpen(!isOpen)

✅ useEffect - Efectos secundarios
   Uso: Cargar datos al montar componente, timers, cleanup

   useEffect(() => {
     const cargarDatos = async () => {
       const data = await getServicios()
       setServicios(data)
     }
     cargarDatos()
   }, [])

✅ useSearchParams - Parámetros de URL
   Uso: Pre-rellenar campo "servicio" en formulario

   const [searchParams] = useSearchParams()
   const servicio = searchParams.get('servicio')

BENEFICIOS:
- Código más limpio que lifecycle methods (componentDidMount, etc.)
- Fácil manejar estado complejo
- Reutilización de lógica con custom hooks

5. ANIMACIONES Y TRANSICIONES SUAVES CON CUBIC-BEZIER
================================================================================

DEFINICIÓN:
Usar cubic-bezier timing functions para crear animaciones naturales y profesionales
en lugar de linear o ease.

EASING FUNCTION ESTÁNDAR:

--transition: 0.3s cubic-bezier(0.4, 0, 0.2, 1);

EXPLICACIÓN:
cubic-bezier(0.4, 0, 0.2, 1)
  ├─ 0.4 = Inicio rápido
  ├─ 0 = Punto de control 1
  ├─ 0.2 = Desaceleración
  └─ 1 = Fin natural

ANIMACIONES DEFINIDAS:

@keyframes slideUp {
  from {
    opacity: 0;
    transform: translateY(30px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

APLICACIÓN:

.header-content {
  animation: slideUp 0.8s ease-out;
}

.button:hover {
  transform: translateY(-2px);
  box-shadow: 0 6px 20px rgba(0, 0, 0, 0.2);
  transition: var(--transition);
}

BENEFICIOS:
- Animaciones profesionales (no robóticas)
- Mejor experiencia de usuario
- Consistencia visual en todo el app

8. VALIDACIÓN AVANZADA CON EXPRESIONES REGULARES (REGEX)
================================================================================

DEFINICIÓN:
Usar regex para validar formatos de datos complejos (email, teléfono, etc.)

IMPLEMENTACIÓN EN CONTACTFORM:

const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/

DESGLOSE:
^           = Inicio de cadena
[^\s@]+     = 1+ caracteres (no espacio, no @)
@           = Literal @
[^\s@]+     = Dominio (no espacio, no @)
\.          = Punto literal (escapado)
[^\s@]+     = Extensión (com, cl, etc.)
$           = Fin de cadena

CASOS VALIDADOS:
✅ usuario@ejemplo.com
✅ juan.perez@empresa.co
✅ mail.123@sub.dominio.com

CASOS RECHAZADOS:
❌ usuario@com (sin dominio)
❌ usuario.com (sin @)
❌ usuario@ (sin dominio)
❌ usuario @ejemplo.com (espacio)
❌ usuario@.com (sin nombre de dominio)

IMPLEMENTACIÓN EN CÓDIGO:

const validarEmail = (email) => {
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/
  return emailRegex.test(email)
}

if (!validarEmail(email)) {
  setError('Email no válido')
}

OTRAS REGEX ÚTILES:

Teléfono: /^\d{9}$/
URL: /^https?:\/\/.+\..+/
Contraseña (8+ chars, mayús, número): /^(?=.*[A-Z])(?=.*\d).{8,}$/

9. SEGURIDAD: PROTECCIÓN ANTI-BOTS
================================================================================

DEFINICIÓN:
Implementar medidas para evitar que bots automatizados envíen spam.

TÉCNICAS IMPLEMENTADAS:

✅ 1. HONEYPOT FIELD (Campo trampa)
   
   <input
     type="text"
     name="website"
     style={{ display: 'none' }}
     value={honeypot}
     onChange={(e) => setHoneypot(e.target.value)}
   />

   LÓGICA:
   - Campo oculto (display: none)
   - Si bot llena el campo → honeypot !== ""
   - Rechazar envío si está lleno

   if (honeypot.trim() !== "") {
     throw new Error("Solicitud sospechosa detectada")
   }

✅ 2. RATE LIMITING (Limitar envíos)
   
   const [lastSubmitTime, setLastSubmitTime] = useState(0)
   
   const canSubmit = () => {
     const now = Date.now()
     if (now - lastSubmitTime < 10000) { // 10 segundos
       return false
     }
     setLastSubmitTime(now)
     return true
   }

✅ 3. VALIDACIÓN DE INTERACCIÓN
   
   Detectar si el usuario realmente interactuó:
   - Focus en campo de email
   - Cambios de valores
   - Sin auto-fill detectado

✅ 4. CAPACCHA (Futuro)
   
   Integrar Google reCAPTCHA v3:
   
   import ReCAPTCHA from "react-google-recaptcha"
   
   <ReCAPTCHA sitekey="YOUR_KEY" onChange={handleRecaptcha} />

FLUJO COMPLETO DE VALIDACIÓN:

1. Usuario llena formulario
2. Valida campos (regex, requeridos)
3. Verifica honeypot (vacío)
4. Verifica rate limiting (no spam)
5. Comprueba interacción real
6. Envía datos

10. CONSUMO DE API/JSON CON ASYNC/AWAIT Y PROMISE.ALL
================================================================================

DEFINICIÓN:
Cargar datos dinámicamente de APIs o archivos JSON con manejo de errores
y optimización.

IMPLEMENTACIÓN:

// api/services.js - Funciones separadas por recurso

export const getServicios = async () => {
  try {
    const response = await fetch('/data/servicios.json')
    if (!response.ok) throw new Error('Error al cargar')
    return await response.json()
  } catch (error) {
    console.error('Error en getServicios:', error)
    throw error
  }
}

// Home.jsx - Cargar múltiples recursos en paralelo

useEffect(() => {
  const cargarDatos = async () => {
    try {
      setLoading(true)
      
      // Promise.all = Cargar TODO simultáneamente (más rápido)
      const [servicios, testimonios, faqs, about] = await Promise.all([
        getServicios(),
        getTestimonios(),
        getFaqs(),
        getAbout()
      ])
      
      setServicios(servicios)
      setTestimonios(testimonios)
      setFaqs(faqs)
      setAbout(about)
      
    } catch (error) {
      setError('Error al cargar datos')
    } finally {
      setLoading(false)
    }
  }

  cargarDatos()
}, [])

VENTAJAS:
- Promise.all: 3x más rápido que fetch secuencial
- Try/catch: Manejo elegante de errores
- Estados: loading, error, success
- Fallback: mockData si falla la API

EVOLUCIÓN:
Cuando tengas backend:

// Antes (JSON local):
const response = await fetch('/data/servicios.json')

// Después (API real):
const response = await fetch('https://tu-api.com/api/servicios', {
  headers: { 'Authorization': `Bearer ${token}` }
})
