================================================================================
PROTECCIÓN DE FORMULARIO - MEDIDAS ANTI-BOT IMPLEMENTADAS
================================================================================

Documento técnico que describe las 3 capas de protección implementadas 
en el formulario de contacto del proyecto Centro de Negocios Santiago SERCOTEC.

Ubicación del código: src/components/ContactForm/ContactForm.jsx

================================================================================
DESCRIPCIÓN GENERAL
================================================================================

El formulario de contacto implementa múltiples medidas de seguridad coordinadas
para detectar y prevenir envíos automatizados de bots y scrapers:

1. Honeypot Field (Trampa para bots)
2. Rate Limiting (Limite de envíos por tiempo)
3. User Interaction Detection (Detección de interacción real)

================================================================================
1. HONEYPOT FIELD - TRAMPA PARA BOTS
================================================================================

OBJETIVO:
Detectar si un script automatizado intenta llenar el formulario.

CÓMO FUNCIONA:

1. Se crea un campo input invisible:
   
   <input
     type="text"
     name="website"
     style={{ display: 'none' }}
     value={honeypot}
     onChange={(e) => setHoneypot(e.target.value)}
   />

2. El campo está oculto del usuario mediante:
   - display: none
   - position: absolute; left: -9999px
   - visibility: hidden
   - tabIndex: -1

3. Bots automatizados (Selenium, Puppeteer, etc.) frecuentemente:
   - Escanean todos los inputs
   - Llenan inputs con datos de prueba
   - No respetan propiedades de CSS

4. Cuando se envía el formulario:
   
   if (honeypot.trim() !== '') {
     // Bot detectado - Rechazar silenciosamente
     console.warn('⚠️ Honeypot field detectado - Posible bot')
     return
   }

VENTAJAS:
✅ Invisible para usuarios reales
✅ Simple de implementar
✅ Muy efectivo contra bots simples
✅ Silencioso (no muestra errores al bot)

LIMITACIONES:
❌ Bots sofisticados pueden usar headless browsers para detectar CSS
❌ No funciona contra todos los tipos de ataques
❌ Requiere complementarse con otras medidas

PRUEBA DE CONCEPTO:

// Para testear manualmente (desde DevTools):
document.querySelector('input[name="website"]').value = "spam.com"
// Ahora envía el formulario - será rechazado

================================================================================
2. RATE LIMITING - LÍMITE DE ENVÍOS POR TIEMPO
================================================================================

OBJETIVO:
Limitar la velocidad de envíos para prevenir spam masivo.

CONFIGURACIÓN:

const RATE_LIMIT_MS = 10000  // 10 segundos mínimo entre envíos
const lastSubmitTime = useRef(0)

IMPLEMENTACIÓN:

En la función onSubmit():

const now = Date.now()
if (now - lastSubmitTime.current < RATE_LIMIT_MS) {
  const segundosRestantes = Math.ceil(
    (RATE_LIMIT_MS - (now - lastSubmitTime.current)) / 1000
  )
  throw new Error(`Por favor espera ${segundosRestantes} segundos`)
}
lastSubmitTime.current = now

FLUJO:
1. Usuario envía primer formulario → Registra timestamp
2. Usuario intenta enviar a los 5 segundos → Rechazado ("espera 5 segundos")
3. Usuario intenta enviar a los 11 segundos → Aceptado + nuevo timestamp

VENTAJAS:
✅ Evita spam repetitivo
✅ Protege contra ataques de fuerza bruta
✅ Accesible para usuarios legítimos (10 segundos es razonable)
✅ Impide envíos accidentales duplicados

DESVENTAJAS:
❌ No impide un único envío malicioso
❌ Un bot puede simplemente esperar 10 segundos
❌ Requiere almacenamiento en servidor para ser completo

ESCENARIOS PREVENIDOS:

Escenario 1: Bot intenta llenar 100 veces
- Intento 1: Aceptado
- Intentos 2-10: Rechazados ("espera X segundos")
- Escenario controlado ✅

Escenario 2: Usuario accidental duplica click
- Primer envío: Aceptado
- Segundo envío (1 seg después): Rechazado ("espera 9 segundos")
- Previene duplicados ✅

================================================================================
3. USER INTERACTION DETECTION - DETECCIÓN DE INTERACCIÓN REAL
================================================================================

OBJETIVO:
Verificar que un usuario real completó el formulario de forma interactiva
(escribiendo, seleccionando, etc.)

IMPLEMENTACIÓN:

Estado de referencia:
const userInteractionRef = useRef(false)

Handlers en cada input:
<input
  onFocus={() => { userInteractionRef.current = true }}
  onChange={(e) => { userInteractionRef.current = true }}
/>

Validación en submit:
if (!userInteractionRef.current) {
  throw new Error('Por favor completa el formulario de forma interactiva')
}

LÓGICA:
1. Usuario hace focus en campo → userInteraction = true
2. Usuario escribe algo → userInteraction = true
3. Usuario hace click/tab → onFocus = true
4. Forma se envía → Verifica si interactuó

CONTRA-MEDIDAS:
- Bot que llena valores directamente sin eventos: DETECTADO
- Bot que simula eventos: PUEDE PASAR (pero headless browsers lo hacen)
- Bot genérico sin JavaScript: BLOQUEADO automáticamente

VENTAJAS:
✅ Detecta bots sin JavaScript
✅ Requiere simulación de eventos (más sofisticado)
✅ Bloquea auto-fill de password managers en algunos casos

LIMITACIONES:
❌ Bots sofisticados pueden disparar eventos
❌ Usuarios pueden interactuar sin escribir (pegar con Ctrl+V)

================================================================================
FLUJO COMPLETO DE VALIDACIÓN
================================================================================

Cuando el usuario hace click en "Enviar mensaje":

┌─ PASO 1: Honeypot Validation
│  └─→ if (honeypot.trim() !== '') return false
│
├─ PASO 2: Rate Limiting
│  └─→ if (now - lastSubmitTime < 10000) return false
│
├─ PASO 3: User Interaction
│  └─→ if (!userInteractionRef.current) return false
│
├─ PASO 4: Required Fields
│  └─→ if (!nombre || !email || !mensaje) return false
│
├─ PASO 5: Email Regex
│  └─→ if (!validEmailRegex.test(email)) return false
│
└─ PASO 6: Send Form
   └─→ Enviar datos (cuando backend esté listo)

RESULTADO:
- Validación exitosa → "¡Mensaje enviado correctamente!"
- Cualquier error → "Error: [mensaje específico]"
- Honeypot lleno → Finge éxito pero no envía (confunde bots)

================================================================================
SEGURIDAD A NIVEL DE SERVIDOR (FUTURO)
================================================================================

Las medidas actuales son CLIENT-SIDE. Para máxima seguridad, cuando implemente
un backend, agregue estas validaciones SERVER-SIDE:

1. VALIDACIÓN EN SERVIDOR:
   - No confíe SOLO en validación cliente
   - Re-valide email regex en servidor
   - Re-valide rate limiting en servidor (por IP)

2. CAPTCHA VERDADERO:
   - Google reCAPTCHA v3 (invisible, basado en score)
   - hCaptcha (alternativa open-source)
   - Cloudflare Turnstile

3. EMAIL VERIFICATION:
   - Enviar código de confirmación
   - Verificar email real antes de procesar

4. IP-BASED RATE LIMITING:
   - Limitar 5 envíos por IP por hora
   - Bloquear IPs sospechosas
   - Usar caché (Redis) para tracking

5. LOGGING Y MONITORING:
   - Registrar todos los envíos (IP, timestamp, datos)
   - Alertar si hay patrones de spam
   - Dashboard para revisar intentos

IMPLEMENTACIÓN EXEMPLO (pseudocódigo):

// backend/routes/contacto.js
app.post('/api/contacto', async (req, res) => {
  const { nombre, email, mensaje } = req.body
  const ip = req.ip
  
  // 1. Validar email regex
  if (!emailRegex.test(email)) {
    return res.status(400).json({ error: 'Email inválido' })
  }
  
  // 2. Rate limiting por IP
  const recentCount = await redis.get(`contacto:${ip}`)
  if (recentCount >= 5) {
    return res.status(429).json({ error: 'Demasiados intentos' })
  }
  
  // 3. Verificar captcha
  const captchaValid = await verifyCaptcha(req.body.captchaToken)
  if (!captchaValid) {
    return res.status(400).json({ error: 'Captcha inválido' })
  }
  
  // 4. Guardar en base de datos
  await contactos.create({ nombre, email, mensaje, ip, timestamp: now })
  
  // 5. Incrementar rate limiter
  await redis.incr(`contacto:${ip}`)
  await redis.expire(`contacto:${ip}`, 3600) // 1 hora
  
  return res.json({ success: true })
})
